# Architecture

useMemo is a single-page React 19 + TypeScript (strict) app built with Vite, with no UI or drag-and-drop libraries. The code is split by responsibility: `types/` holds the shared model (`Note`, `Point`, `Size`, `Rect`, the `NotePattern` union and `SaveStatus`), `constants/` the product rules (size and text limits, patterns, storage key), and `utils/` the pure functions that do the actual work: geometry, note sizing, layering, the `isNote` type guard and the pattern geometry. `services/notesStorage` is the only module that touches `localStorage`, `store/` holds a single Zustand store (`useNotesStore`) whose actions call those pure functions, `hooks/` turns pointer gestures into store actions (`useDrawNote`, `useMoveNote`, `useResizeNote`, `useDismiss`), and `components/` renders the board, one folder per component. Because the rules live in plain functions and the store works outside React, most of the logic is tested without rendering anything.

Zustand was chosen over Redux or React Context because components subscribe to exactly the slice they read through selectors, so a change re-renders only what depends on it, with almost no boilerplate. Drag and resize are built on native Pointer Events with pointer capture: while a gesture is in progress the offset or the size lives in the component's local state and is applied with `transform: translate3d()` or a live preview, and the store is written once, on pointer up. `Note` is wrapped in `React.memo`, handlers read the store with `getState()` instead of subscribing, and a drag only starts after a 4px tolerance, so moving one note never re-renders the others and clicks never flicker. The dragged note and the trash zone stay in sync through a small shared `drag` state (`{ id, overTrash }`), and the hit test is a rectangle intersection in screen coordinates.

Persistence is local only. On start, `persistNotes` reads the versioned key `useMemo:notes:v1` before the first render, keeps only the entries that pass the `isNote` guard (and drops duplicates), and fits their sizes to the limits, so corrupted data never breaks the board. Every change to `notes` is saved with one debounced write (300 ms) and flushed on `pagehide`; saving never throws and returns a `SaveStatus` that the header shows ("Saving…", "All changes saved", storage full or unavailable). Typing does the rest of the safety work: `strict` and `noUncheckedIndexedAccess`, no `any`, a branded `NoteId`, a `NotePattern` union that drives the 8 inline SVG patterns through a `Record`, and type guards at the only boundary with untrusted data. The full decisions are in the [RFC (DCU-1)](https://marinaziembar-team.atlassian.net/browse/DCU-1).
